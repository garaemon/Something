# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

"Something" is a macOS utility app built with SwiftUI that operates as a background service. The app is designed to be triggered via global hotkey (Cmd+Shift+X by default, configurable in the settings window) and automatically hides when it loses focus, making it behave like a quick-access tool rather than a traditional desktop application.

## Build Commands

`Something.xcodeproj` is generated by [XcodeGen](https://github.com/yonaskolb/XcodeGen) from `project.yml` and is not tracked in git.
Edit `project.yml` instead of changing project settings in Xcode.
[mise](https://mise.jdx.dev) installs XcodeGen and defines the tasks.

Install tools:
```bash
mise install
```

Generate the Xcode project:
```bash
mise run generate
```

Build the project (generates the project first):
```bash
mise run build
```

Build for release:
```bash
mise run build-release
```

Run the unit tests (`SomethingTests`):
```bash
mise run test
```

The test run keeps its result bundle with code coverage in `build/Test.xcresult`.
The vendored `ThirdParty/pocketpy/pocketpy.c` is built without coverage instrumentation, so the coverage counts only the app sources.
Print the coverage of the last test run as Markdown:
```bash
mise run coverage
```

Set `COVERAGE_BASE_REF` to add the coverage of the lines changed since that ref, and the uncovered ones among them.
The changed lines come from the working tree, including uncommitted edits but not untracked files, so run the tests again after an edit.
Only sources under `Something/` count, so vendored code such as `ThirdParty/` stays out:
```bash
COVERAGE_BASE_REF=origin/main mise run coverage
```

CI posts the same report, with the changed lines measured against the base branch, as a sticky comment on each pull request from this repository, and updates the comment on every push.

Format the app sources with swift-format (`.swift-format`):
```bash
mise run format
```

Lint the sources with these tools:

- swift-format and [SwiftLint](https://github.com/realm/SwiftLint) (`.swiftlint.yml`) check the app sources. Tests are excluded, and warnings fail.
- `closure-label-lint` (`Tools/ClosureLabelLint`) reports trailing closures that hide a closure label in the app sources. It is a swift-syntax package, and its first run builds swift-syntax for a few minutes.
- [ShellCheck](https://www.shellcheck.net) checks the shell scripts (`*.sh`, `*.bash`, and the hooks in `.githooks/`).

```bash
mise run lint
```

Run the unit tests of `closure-label-lint`:
```bash
mise run test-lint-tools
```

Install the Git hooks in `.githooks` (once per clone; worktrees share the setting):
```bash
mise run install-hooks
```

The hooks do the following:

- `.githooks/pre-commit` runs the linter on every commit that stages a Swift file under `Something/`. `git commit --no-verify` skips it.
- `.githooks/post-checkout` links `Configs/Local.xcconfig` into each new worktree. See [Code Signing](#code-signing).

Each worktree keeps its own `Tools/ClosureLabelLint/.build`, so the first pre-commit run in a new worktree builds swift-syntax for a few minutes. Run `mise run lint` once after creating a worktree to build it up front.

The code follows the Google Swift Style Guide with 4-space indentation. Read [STYLE_GUIDE.md](STYLE_GUIDE.md) before writing Swift code, and run `mise run format` after editing it.

Build and launch the app:
```bash
mise run run
```

Build products go to `build/` (ignored by git).

### Code Signing

Without extra setup, builds are signed ad hoc.
macOS ties the permissions of an ad hoc build to its exact binary, so every rebuild asks for them again.
The permissions are Accessibility and the access to `~/Documents` and `~/Downloads`.
To keep the permissions across rebuilds, create `Configs/Local.xcconfig` with your team ID and build.
The following command overwrites the file if it already exists:

```bash
echo 'DEVELOPMENT_TEAM = <your team ID>' > Configs/Local.xcconfig
mise run build
```

`Configs/Signing.xcconfig` includes `Configs/Local.xcconfig` when the file exists. Git ignores `Configs/Local.xcconfig`.

Git does not copy an ignored file into a new worktree.
With the hooks installed (`mise run install-hooks`), `.githooks/post-checkout` links the main checkout's `Configs/Local.xcconfig` into each new worktree.
For a worktree created before the hooks, link the file by hand:

```bash
mise run link-local-config
```

## Architecture

### Core Components

- **SomethingApp.swift**: Main app entry point using SwiftUI's App protocol. Uses Settings scene to prevent default window appearance on launch.
- **AppDelegate.swift**: Handles app lifecycle, global hotkey registration (HotKey library), and window management. Switches the activation policy between `.regular` and `.accessory` to show or hide the Dock icon as `AppSettings` says.
- **AppDelegate+Dock.swift**: Opens the launcher when the user clicks the Dock icon of the running app, and switches the activation policy while keeping the key window, such as the settings window, in front.
- **SomethingWindowController.swift**: Custom NSWindowDelegate that implements auto-hide behavior when window loses focus, and reports resizes so that AppDelegate can reposition the mascot panel.
- **LauncherView.swift**: Launcher UI in the style of Emacs anything.el. Lists the windows of running applications, then every application, then the git repositories under the configured folder (`~/ghq` by default), and narrows the list on each keystroke. A query that reads as arithmetic, such as `10 + 30`, lists its result first. Commands such as settings, scratch, and capture come next, before the files. A non-empty query also lists up to 50 matching files under the configured file folders (`~/Downloads` and `~/Documents` by default). It then lists Google Search and Google AI Mode at the end, without narrowing. Picking a window brings it to the front; picking an application launches it; picking a repository opens its directory in Finder; picking a file opens it in its default application (a second action, Reveal in Finder, is in the action list); picking a web search opens it in the default browser; picking a calculator result copies it to the clipboard; picking "Python Scratch" opens the scratch window. Keys: Up/Down or C-n/C-p move, and keep moving while held; Return picks the row, Esc or C-g closes. Tab or C-z swaps the list for the actions of the highlighted row, narrowed by the query field like the candidates but in their own order; Return runs the highlighted action, and Esc or C-g goes back to the candidates with their query and highlight instead of closing. Clicking a row picks it.
- **LauncherKeyBindings.swift**: Resolves a launcher key press, including the repeats of a held key, to a command (move the selection, show the actions, or close). A held Esc closes only once.
- **LauncherViewModel.swift**: Query, narrowed candidates, and selection state for the launcher, plus the action list mode (target candidate, action query, narrowed actions, action highlight), where moving and activating act on the actions. Lists the candidates of its sources in order, swaps in a rescanned source by its identifier, and runs the default action of the picked candidate.
- **LauncherCandidate.swift**: One launcher row: identifier, name, icon, kind, and a list of actions. The first action is the default one. Equality compares identifiers only. The kind (Window, App, Repo, File, Web, Settings, Calc, Scratch, Capture) is a badge at the right end of the row, so that a window of an application stands apart from the application itself.
- **CandidateSource.swift**: The `CandidateSource` protocol, in the style of anything.el sources. A source produces the candidates of one kind for a query. A new kind of candidate adds a source, plus a case of `LauncherCandidateKind` with its badge label and symbol.
- **ApplicationSource.swift**, **WindowSource.swift**, **RepositorySource.swift**, **FileSource.swift**, **WebSearchSource.swift**: The sources of applications, windows, ghq repositories, files, and web searches. The file source lists nothing for an empty query, and keeps the catalog's most-recent-first order instead of sorting by name.
- **ApplicationMatcher.swift**: Case-insensitive AND match of whitespace-separated patterns. Prefix matches of the first pattern rank first. The generic `filterItems` narrows any candidate by a name closure, such as windows by app name and title.
- **ApplicationCatalog.swift**: Scans `/Applications`, `/System/Applications`, and `~/Applications` for `.app` bundles, and adds Finder.
- **LaunchableApplication.swift**: Name and URL of one application bundle that the launcher lists.
- **SwitchableWindow.swift**: Application name, title, and Accessibility element of one window that the launcher lists.
- **WindowCatalog.swift**: Lists standard windows of running regular applications through the Accessibility API, and asks for the Accessibility permission on first use.
- **WebSearch.swift**: Search engines as data (`WebSearchEngine`: label, SF Symbol, base URL, fixed parameters) and the percent-encoded results URL for one query (`WebSearch`).
- **GhqRepository.swift**: Path relative to the repositories folder, such as `github.com/owner/name`, and URL of one repository that the launcher lists.
- **RepositoryCatalog.swift**: Scans a root folder for directories that hold a `.git` entry, up to six levels deep and through symbolic links, without running ghq or a shell. A custom `ghq.root` is not read. An injectable `loadRepositories` closure, which takes the root, keeps tests off the real tree.
- **LocalFile.swift**: Name (the folder's name plus the path inside it, such as `Downloads/reports/q3.pdf`) and URL of one file that the launcher lists.
- **FileCatalog.swift**: Scans the file folders for regular files and packages, most recently modified first. Skips hidden files and build output folders such as `node_modules`, stops four levels deep, and keeps at most 20,000 files per folder. An injectable `loadFiles` closure keeps tests off the real folders.
- **BackgroundListLoader.swift**: Caches the last load of a list keyed by a setting, such as the repositories folder or the file folders, and loads it again on its own background queue, one load at a time. A load whose key changed meanwhile is dropped and the new key is loaded. AppDelegate owns one for repositories and one for files.
- **WindowRaiser.swift**: Unminimizes and raises a window, then activates its application.
- **ApplicationIconCache.swift**: Caches the icons of applications and file types so that list rows do not reload them on every render.
- **BalanceSimulation.swift**: Pure two-wheeled inverted pendulum with pole-placed state feedback, a small constant disturbance, and a fixed 1/240 s step. The launcher state only sends it a target position and kicks.
- **MascotState.swift**: Mascot state (`appearing`, `idle`, `typing`, `noMatch`) derived from the query, the candidate count, and whether the window just opened, plus the screen text for each state.
- **MascotChoreography.swift**: Per-state target position, lift, yaw, head, and hand motion from the approved three.js prototype. The entrance rises from behind the launcher's top edge, or drops in from above beside it, and lands with a kick.
- **MascotMailbox.swift**: Lock-protected handoff of state and query from SwiftUI to the SceneKit render thread.
- **MascotAnimator.swift**: Steps the simulation with a fixed-step accumulator and maps it to a `MascotFrame` (pose, wheel roll, screen text). No SceneKit, so it is testable.
- **MascotModel.swift**: The robot's parts as `Codable` data, with the prototype robot as the default, so that skins can later be loaded from a file. `recolored(headColor:bodyColor:)` repaints the skin colors.
- **MascotToon.swift**: Toon-shading and outline shader modifiers with their tunable numbers in one place.
- **MascotSceneBuilder.swift**: Builds the SceneKit nodes from `MascotModel` with toon materials, inverted-hull outlines, in-place recoloring of a built rig, a ground shadow for the side placements, and the camera, which is aimed so that the ground line lands on the placement's `groundLineFraction` of the view height.
- **MascotPanelLayout.swift**: `MascotPlacement` (top, left, right) and the pure geometry of the mascot panel (220x220 pt; on the launcher's top edge, or beside it with a 30 pt overlap and the ground line level with the launcher's bottom edge). Also picks the placements that fit the screen, and the camera pitch that matches the placement.
- **MascotPanel.swift**: Borderless, transparent, click-through `NSPanel` that never becomes key or main, with an `NSHostingView` of `MascotOverlayView`.
- **MascotOverlayView.swift**: Observes `LauncherViewModel`, derives the mascot state, and owns the entrance timer.
- **MascotView.swift**: `NSViewRepresentable` around a transparent `SCNView`, which builds the shapes once and repaints only the colors when `model` changes, and the render delegate that applies each animator frame and redraws the screen texture when the text changes.
- **HotKeyBinding.swift**: `HotKeyCommand` (`openLauncher`, `openScratch`, `openSettings`; `Codable` string enum; a command with data needs a new JSON shape and a migration), `HotKeyBinding` (id, `KeyCombo`, `ModifierSides`, command; JSON through the Carbon key code and modifiers; a binding saved without `modifierSides` loads as either side; `shortcutDescription` such as "Right ⇧E"), and `HotKeyBindingValidator`, which rejects a combination with the same sides that another binding holds and suggests a free one for a new binding.
- **LLMProvider.swift**: The `LLMProvider` protocol (one method, `streamCompletion(prompt:)`, returns an `AsyncThrowingStream<String, Error>` of text chunks, so that tests inject a fake) and the typed `LLMProviderError` (server not running, HTTP error with the server's message such as a missing model, timeout, an error the server reports inside a started stream, malformed response). No AI command uses it yet.
- **ChatCompletionStreamParser.swift**: Pure parser of one server-sent-events line of an OpenAI-compatible chat completion stream (`data:` JSON delta, `[DONE]`; blank, comment, `event:`, `id:`, and `retry:` lines skipped; an `error` event becomes `streamError`).
- **LocalLLMProvider.swift**: `LLMProvider` for the OpenAI-compatible `/chat/completions` endpoint on localhost (Ollama, LM Studio, llama.cpp server) with `stream: true`. The `LLMLineTransport` closure sends the request; the default uses `URLSession.bytes`, and tests inject a fake. The default timeout is 300 s between received bytes, because the first request after idle loads the model. A stream that ends without `[DONE]` is malformed. The app has no sandbox entitlements, so the localhost connection needs no change.
- **AppSettings.swift**: User preferences (hot key bindings, saved as JSON; a saved single `hotKey` from before bindings migrates to an `openLauncher` binding; repositories folder, file folders, Dock icon, mascot head and body colors, local LLM base URL `http://localhost:11434/v1` and model name), saved to an injectable `UserDefaults` on every change.
- **SettingsView.swift**: The settings window content: a list of hot key bindings (command picker, recorder, remove button) with an add button, repositories folder picker, Dock icon toggle, file folder list with add and remove buttons, language model base URL and model fields, a live mascot preview, mascot color pickers, and Restore Defaults.
- **HotKeyRecorderView.swift**: Button that records, for one binding, the next key press as the hot key through a local key monitor, plus a Left/Right checkbox that keeps the side of each held modifier. Esc cancels.
- **HotKeyRecording.swift**: Turns a key press into a `KeyCombo` and `ModifierSides` (`RecordedShortcut`), and rejects a press without Command, Option, or Control, except one that holds a sided modifier, such as Right Shift + E.
- **ModifierSides.swift**: `ModifierSides` (per modifier: either, left, or right; `isSided`), `ModifierFlagBits` (the device-dependent `NX_DEVICE*KEYMASK` bits, which `NSEvent.modifierFlags.rawValue` and `CGEventFlags` both carry), and the pure `HotKeyEventMatcher.matches(keyCode:flags:keyCombo:sides:)`. A sided modifier rejects the other side held at the same time, and any modifier outside the combination rejects the match. The generic bit says whether a modifier is down, because a device bit can outlive the release. Caps Lock and Fn are ignored.
- **SidedHotKeyMonitor.swift**: Runs the bindings with a sided modifier through an event tap, because Carbon (HotKey) cannot tell left from right. Bindings without a side stay on HotKey, so that the default hot key needs no permission. Installs the tap only while a sided binding exists and the Accessibility permission is granted (never prompts; `WindowCatalog` asks), reports `status` (inactive, active, needsAccessibility, tapUnavailable) to the settings window, swallows a matching key-down, runs the command on a later run loop turn, and runs a held key once. `KeyEventTapInstalling` is the injectable installer, so that tests never install a real tap.
- **CGKeyEventTapInstaller.swift**: The real `KeyEventTapInstalling`: a session, head-insert, key-down `CGEventTap` on the main run loop, which turns itself on again after `tapDisabledByTimeout` or `tapDisabledByUserInput`. Untested, because a real tap intercepts the developer's keystrokes.
- **Calculator.swift**: Recursive descent evaluator of `+ - * / % ^`, unary minus, and parentheses (`×` and `÷` too). Rejects an expression without a binary operator, such as "2024" or "-5", and numbers chained by two or more hyphens or slashes, so that "2026-11-15" stays a search. Formats integers without a decimal point and rounds fractions to 12 significant digits.
- **CalculatorSource.swift**: Launcher source that lists `= <result>` for an arithmetic query, and copies the result on pick.
- **SettingsSource.swift**: Launcher source that lists "Something Settings" for queries such as "settings" or "pref", and opens the settings window.
- **PythonInterpreter.swift**: Runs a `PythonBlock` (leading source plus a last statement whose expression value is echoed) on the embedded pocketpy VM, and returns the printed output and the exception type and message without stack frames. Variables persist between runs until `reset()`. pocketpy keeps process-wide C state, so the app has one shared interpreter that serializes runs on its own queue, and a watchdog stops a run with `TimeoutError` after 2 s of process CPU time by default. The watchdog checks between bytecodes only, so a long C call such as `time.sleep` is not stopped. Printed output is capped at 100,000 bytes per run, `input()` reads an empty line, and `exit()` raises `SystemExit` instead of quitting the app. Swift reaches pocketpy through `Something-Bridging-Header.h`.
- **ScratchStore.swift**: Reads and writes the scratch buffer at `~/Library/Application Support/Something/scratch.py`, and starts a buffer that was never saved with a one-line comment. A file that exists but cannot be read as UTF-8 makes the load throw instead.
- **ScratchAutosaver.swift**: Saves the latest text once typing pauses for 1 s, and saves the pending text at once on `flush()`.
- **ScratchWindowController.swift**: The `*scratch*` window: a plain-text `NSTextView` in a monospaced font with smart quotes, dashes, and spelling correction off, so that Python source stays valid. Saves through `ScratchAutosaver` while typing and when the window closes, and shows a failed save in the window subtitle. A local key monitor sends C-j and C-c sequences in the editor to `ScratchRunner`, except while an input method composes text. A play button at the right edge of each block runs that block through `ScratchRunButtons`. `ScratchHighlighter` colors the Python source after every edit. The window subtitle shows `Running…` during a run or a reset, and says so when a run dropped its results. A scratch file that cannot be read opens read-only, without the keys, so that no autosave overwrites it, and the next open reads the file again. A failed save stays pending and is retried on the next save, such as when the app quits.
- **ScratchBlockParser.swift**: Finds the blocks of the scratch buffer (paragraphs of code; a blank line before an indented line or an `else`, `elif`, `except`, or `finally` clause does not end one), the `# => ` and `# !! ` result lines under each, and splits a block before its last top-level statement into a `PythonBlock`, keeping decorators with their definition. Lines inside a triple-quoted string stay in the block of the string, and each `\r` or `\n` in the output starts a result line.
- **PythonLineScanner.swift**: Carries open triple-quoted strings and bracket depth from line to line, skipping short strings and comments, so that the parser can tell where a top-level statement starts. A trailing backslash is not tracked.
- **ScratchKeyBindings.swift**: Resolves C-j (run the block at the cursor), C-c C-c (run every block), and C-c C-k (reset the interpreter). An undefined key after C-c types nothing, as in Emacs.
- **ScratchRunner.swift**: Runs blocks on a background queue, keeps the text view read-only meanwhile, then replaces the result lines under each block bottom-up in one undo group. A reset also runs off the main thread, a command during a run is ignored, and a run whose text changed meanwhile (undo still works on read-only text) drops its results.
- **PythonSyntaxScanner.swift**: Finds the spans to color in Python source: keywords, builtins (not after a dot), strings with their prefixes, comments, numbers, decorators at the start of a line, and the `# => ` and `# !! ` result lines. Triple-quoted strings carry over to the next line. Ranges are UTF-16, so that they apply to `NSTextStorage` as they are. The inside of an f-string is not split into expressions.
- **ScratchHighlighter.swift**: Colors the scratch text view from `PythonSyntaxScanner` with system colors, which follow dark mode. The saved file holds the plain text, and the colors go into the text storage outside `shouldChangeText`, so that the undo history skips them.
- **ScratchRunButtons.swift**: Places a play button at the right edge of the first line of each block, as subviews of the text view so that they scroll with the text, and moves them again when the text changes or the window resizes. A button covers the end of a line that reaches it. The buttons never take the keyboard focus from the editor.
- **ScratchSubtitle.swift**: Builds the scratch window subtitle from the run status (`Running…`, dropped results) and the last save failure, so that neither erases the other.
- **ScratchSource.swift**: Launcher source that lists "Python Scratch" for queries such as "scratch" or "python", and opens the scratch window.
- **CaptureSource.swift**: Launcher source that lists "Record Screen" (opens Screenshot.app), "Capture Area to Clipboard" (`screencapture -ic`), and "Capture Window to Clipboard" (`screencapture -iwc`) for a matching query. A `CaptureCommand` value goes to an injected closure; AppDelegate hides the launcher, waits `captureDelay`, then opens the app or runs the process.
- **CaptureLauncher.swift**: Opens the application or runs the process of a `CaptureCommand`. **AppDelegate+Capture.swift** hides the launcher and starts it after `captureDelay` (0.3 s).

### Key Behavioral Patterns

- **Dock Icon Setting**: The app shows its Dock icon by default (`.regular` activation policy). Turning off "Show icon in Dock" in the settings switches it to `.accessory`, which keeps the app out of the Dock, the Command-Tab switcher, and the menu bar.
- **Global Hotkey Activation**: Uses HotKey library for every binding in `AppSettings` (Cmd+Shift+X opens the launcher by default). AppDelegate registers all bindings again when the list changes, and pauses them all (the sided monitor too) while the settings window records a new one. A binding with a left or right modifier goes to `SidedHotKeyMonitor` instead of HotKey, and AppDelegate retries the tap whenever the app becomes active. A recorded combination that another binding holds beeps and is ignored.
- **Dock Icon Click**: Clicking the app's icon in the Dock, or opening the app again from Finder, while the app runs opens the launcher, like the hot key. Switching to the app with Command-Tab opens nothing, because macOS sends no reopen event for it.
- **Scratch Window**: AppDelegate owns one scratch window and reuses it, like the settings window. The app saves pending edits when it quits.
- **Settings Window**: The app has no menu bar while the Dock icon is off, so the launcher lists a settings row. AppDelegate owns one settings window and reuses it. Command-comma opens the same window, because SomethingApp replaces the stock Settings… command. Mascot colors apply on the next launcher open; the preview in the settings window repaints at once.
- **Auto-Hide on Focus Loss**: Window automatically hides when user clicks away or switches apps
- **Single Window Management**: Only one popup window exists at a time, reuses existing if already open. The mascot panel is a child window of the launcher, created and closed with it. AppDelegate picks its placement at random on each open, among those that fit the screen.
- **Cached Application Scan**: AppDelegate shows the previous scan immediately and rescans on a serial background queue at launch and on every open. A finished scan updates the open launcher.
- **Cached Repository List**: AppDelegate shows the previous repository scan immediately and rescans the repositories folder from `AppSettings` on a serial background queue at launch, on every open, and when the folder changes. An open skips the refresh while a previous one is still running. A scan of a folder that changed meanwhile is dropped and the new folder is scanned.
- **Cached File List**: Like the repository list, through `BackgroundListLoader`: the previous scan shows immediately, and the file folders from `AppSettings` are rescanned at launch, on every open, and when the folders change. `~/Documents` and `~/Downloads` are protected folders, so macOS asks for access on the first scan.
- **Fresh Window List**: AppDelegate lists windows on its own background queue on every open without caching. The Accessibility API returns only windows on the current Space.

  - Repository: https://github.com/soffes/HotKey

### Window Management Strategy

The app implements a sophisticated window lifecycle:
1. Window created on-demand when hotkey triggered
2. Custom SomethingWindowController manages window delegate responsibilities
3. Window automatically hides on focus loss (windowDidResignKey)
4. Strong references maintained in AppDelegate during window lifetime
5. Cleanup handled via closure-based callback system (onWindowRelease)
